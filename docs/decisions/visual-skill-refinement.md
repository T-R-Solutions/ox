# Visual creation skill refinement

Adopted locally on 2026-11-16 under the maintainer's explicit request to analyze
ui-design-skills-pack and ui-ux-pro-max-skill and improve local visual skills.

Keep the 31 skill identities, profile membership and existing bridges. Refactor
three existing methods: design-system owns reusable composition, typography,
tokens and patterns; design-review owns task-grounded comparison and visual QA;
iced-engineering owns native translation and observed geometry/interaction.
Software architecture retains system boundaries and quality attributes. Creating
a catchall UI skill or importing every upstream entry would duplicate ownership.

Author original concise references from inspected sources, with pinned provenance.
No upstream package, runtime, font service, generator or installer is adopted.
Existing DESIGN.md owns product identity and native constraints. Style catalogs,
industry mappings, scores, arbitrary dimensions and marketing defaults are proposals,
not evidence of usability or permission to overwrite a product system.

Preserve historical copy identities. A bounded successor registry records only the
changed skill paths, the checker integration and reviewed byte transformations; reconstruct predecessors in
memory rather than introducing backup copies. Exact current and predecessor hashes,
closed inventory and rejection tests protect against unreviewed edits or downgrade.
This does not renew historical acceptance or create general path exemptions.

Acceptance and source limitations belong to visual-skill-refinement. Existing
skill-native-visual-method and product acceptance remain independent. Revisit when
actual use reveals missing guidance, upstream methods change materially, or a new
responsibility cannot fit these existing skills without ambiguity.
