# ADR — Technical documentation visual method

Adopted for the maintainer's 2026-11-04 request to refactor technical-documentation
for Mermaid and professional imagery, translating aesthetic terms into measurable
technical criteria. This is a library method revision, not a new skill/profile
entry, product feature, rendering dependency installation or application redesign.

D-01: retain source-grounded contracts and verification. Add visual planning,
Mermaid model selection, coherent SVG role iconography, data/image provenance and
measurable review gates with progressive references. Numbers for typography,
spacing/density and viewports are editorial defaults; cited contrast rules have
W3C provenance. These gates do not claim universal beauty or WCAG certification.

D-02: actual destination renderer support governs icon registration and syntax.
Unsupported rich diagrams use verified self-contained export plus editable source
or remain explicitly unverified. Never silently equate plain shapes/emoji with
requested designed illustrations. No arbitrary minimum image/chart count; no
invented data/screenshots or unapproved remote editor upload.

D-03: register exactly the skill entry, its bridge and four new references in
`docs/validation/technical-documentation-visuals-20261104/revision.json`.
Existing skill/bridge bytes are preserved under before/*.bin with exact hashes.
A bounded predecessor layer resolves only matching current bytes before older
preservation layers; unknown mutations remain errors. New resources are allowlisted
only by exact path/current content. Old manifests, UI metadata, profile, archives
and source hashes are unchanged. Missing/escaping/symlinked preimages or registry,
duplicate records/properties, unexpected scope and mutations must be rejected.

Alternatives rejected: overwriting historical digests; bypassing copied-resource
checks for all documentation files; adding another skill; mandatory CDN/image
services; treating aesthetic adjectives or parse success as visual acceptance.

The preexisting README guard failure is preserved, not waived or repaired here.
Shared consumer evidence keeps exact historical observations; new consumer checks
are recorded independently and cannot turn an inherited failing global check into
a passing one. Review when method scope, renderer, resource inventory or preservation
protocol changes. Acceptance is in sdd/features/technical-documentation-visuals/.
