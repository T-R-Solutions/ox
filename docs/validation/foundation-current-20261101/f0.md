## Current diagnosis and minimal boundary

The immediate sequencing blocker is adoption of the F0 boundary, but closure is
also blocked by incomplete evidence coverage. It is not established that adoption
alone would finish F0, nor that new foundation code is necessary. The expanded
quality proposal requires a fresh criterion-level inventory distinguishing implemented
and evidenced, implemented without sufficient evidence, absent, and justified outside
scope; these labels remain separate from the five acceptance states. The source
inspection establishes one concrete missing implementation: durable history. Under
the proposed boundary it belongs to the separate pre-MVP delivery, not F0.

Read-only comparison in `../f0-reconciliation-20261101/decision-preparation/product-bindings.json`
found no mismatches in 3,514 declared input/artifact bindings across 38 observations
of bootstrap, host, runtime, verifier and local-task-ui. This establishes byte
agreement only. It does not authenticate historical runs, reobserve today's display
environment, discover undeclared dependencies or approve the seven F0 rows.
The earlier reference to check/fmt/clippy/test logs under foundation-current was
not resolvable; use raw artifact paths in the individual feature envelopes.

For F0-P03, inspect host tests `real_process_negotiation_shutdown_and_recovery`,
`incompatible_and_unauthorized_are_rejected`,
`malformed_oversized_and_wrong_correlation_fail_closed` and
`timeout_and_crash_are_distinct_and_bounded`. For F0-P05, inspect verifier cases
`approval_requires_observation_not_completion_claims`,
`failure_history_survives_repair_and_content_invalidation_is_selective`,
`incomplete_and_not_applicable_are_not_approval` and
`contradictory_current_pass_does_not_erase_observed_failure`, together with UI
`real_result_identity_history_invalidation_and_preservation` and the graphical
acceptance review. These are existing candidate oracles, not new execution results.

Proposed minimum: existing Rust/Iced foundation; bounded trusted local host/runtime
contracts; controlled task UI; independent verification, preservation and current
input semantics. No requirement to integrate the host into the UI, support a real
agent, implement full engines or deliver persistent history just to close F0.
This proposal retains all original obligations for explicit disposition; it does
not waive a currently applicable policy or silently shrink an adopted criterion.
