Retain actionable error wording near the relevant item or field, preserve input and provide supported recovery. Compare one terse actionable explanation with badge-plus-detail using the same error and task. Failure condition: a person cannot identify the affected project/field, distinguish failure from pending/unavailable, or find recovery without guessing. No observed failure or violation is claimed yet.
2. Reducing labels may hide distinctions users need to choose a project or understand an action. First reduce whitespace or defer optional metadata; retain action and identity wording that communicates consequences. If shortening labels, show exactly what text changes and where the full value is reachable with keyboard as well as pointer. Compare identical Portuguese labels and similar long paths across densities. Check whether actions remain distinguishable, full identity stays inspectable and focused labels/actions remain legible. An observed density gain alone would not prove task improvement.

A fixed value may be a valid implementation of a tested constraint; the objection concerns making one value universal without content/geometry evidence. Compare side-by-side and stacked/switched detail treatments immediately above and below that threshold and in short windows.

Prioritize any demonstrated missing recovery or unreachable task first, then unreadable/ambiguous identity or focus loss, then density consistency.
