## Search, reasoning and generation

- `src/ui-ux-pro-max/scripts/core.py`: 12 domains, 22 stacks. BM25 uses k1=1.5,b=.75, normalized lexical terms, short stopwords/synonyms, cached CSV/index signatures. Domain keyword routing can misroute ambiguity; explicit domains reduce that. Thresholds/coverage can abstain; exact style/landing/stack identities bypass lexical thresholds but still respect applicability filters. Deprecated style records redirect/resolve parents; RTL is applicability metadata filtered after scoring, not a quality score. Stack rows distinguish current, migration and legacy versions. These are meaningful retrieval safeguards, not empirical proof that chosen styles fit Ox.
- `reasoning_contract.py`: closed JSON condition/action grammar (constraint/style/pattern/mode), duplicate keys/actions rejected, no executable data. Conditions match English keyword phrases. No hidden intelligence: deterministic curated rules, not inference or user research.
- `design_system.py` generation: product top-1 → exact UI_Category reasoning → search style/color/typography/landing → prioritized style + palette mode selection. Returns source identities, activated rules, default/derived-color markers. Missing products/rules may fall back to General, Hero+Features+CTA, Minimalism/Inter/blue. Those defaults are unsuitable as silent native workbench decisions. Contrast calculations are about selected color pairs; they do not inspect composited hover/focus/disabled controls or assistive behavior. Derived dark palettes are candidates, not validated themes.
- Optional variance/motion/density dials bias style retrieval, attach GSAP snippets, and replace spacing scales. Numeric dials are not measured UX/density outcomes. Native input/density semantics require content/hit-target/keyboard constraints. `--stack` is explicitly ignored by `--design-system` with a stderr note; stack advice needs a separate query. There is no Iced dataset.
- `search.py` supports explicit domain/stack, 1–20 results, full/JSON, RTL applicability, generator/tokens and preview. Default text truncates some fields at 300 characters while retaining critical code/checklist columns intact. Main entry advises one intent, 2–5 terms, one corrective retry, explicit no-match/fallback disclosure and no persistence of unverified results: useful decision discipline, not a required new Ox search engine.

## Data census and utility

Main catalog: 89 style rows (51 active,29 supplemental,9 deprecated; 80 searchable via identities),192 products,192 palettes,192 reasoning profiles,74 font pairings,1934 fonts,105 curated icons,1512 icon catalog entries,120 UX guidelines,17 motion presets,25 chart rows,34 landing patterns,32 app-interface rows,44 React performance rows,22 stack files/1278 stack guidelines.

- Styles/products/reasoning: aids brainstorming and vocabulary. Industry-to-aesthetic mapping is a hypothesis; local task, brand and content take precedence. Layout archetypes (sidebar, split, table) are distinct from visual finish (glass, dark, brutalism). Do not force both dimensions together.
- Colors: semantic foreground/background/on-action pairs help specify role relationships. Existing Ox theme/token authority supersedes suggested palettes; verify actual rendered states and never use a root palette as blanket accessibility approval.
- Typography/fonts: distinguish display vs operational text; examine glyphs, accents, identifiers, fallback, actual metrics and licenses. Catalog availability and popularity do not imply local assets, permitted redistribution, readable native rendering or request authorization for downloads.
- Icons: contextual meaning and allowed contexts are useful. Same glyph may be decorative, meaningful or interactive. Catalog naming is not a license, native renderer test or sufficient accessible control label.
- UX/app-interface: useful coverage of error recovery, text overflow, compact labels, IME/composition, RTL, focus, reduced motion and status announcements. Platform thresholds/units must stay platform-specific; web CSS, mobile pt/dp and desktop logical px are different contracts. A checklist cannot establish WCAG conformance.
- Charts: encode task/data semantics before selecting type; include units/provenance/non-color signals and text/table fallback. Catalog accessibility grades/library suggestions are editorial, not observed measurement. Do not fabricate series/data to fill a chart.
- Motion/landing/react: marketing composition/GSAP and framework tips are conditional references, not operational desktop defaults. Reserve layout for loading/errors without forcing decorative motion, hero sections or conversion objectives.
- Stacks: web React/Next/Vue/Svelte/Astro/Angular/Nuxt/Tailwind/shadcn/Laravel/Three.js; mobile SwiftUI/RN/Flutter/Compose; desktop JavaFX/WPF/WinUI/Avalonia/Uno/UWP. Reuse general principles only; APIs must be read against actual Iced version/consumer. Full count/category census is in companion JSON.

`data-provenance.json` and catalog summary carry verifiedAt/status/sources and explicit scope boundaries. Some dataset provenance is dated 2026-08-13 while summary is 2026-11-04: these are upstream records, not fresh independent verification performed today. Font licenses/icon snapshots need asset-level examination at adoption.

## Persistence, preview, distribution and tests

Generator creates project-specific MASTER.md/page overrides and DTCG/CSS token exports. Single files publish through same-directory temporary files, fsync, exclusive hard-link or replace with force; project/page slugs constrain path segments. These mechanisms improve no-overwrite behavior but do not establish atomic consistency for the entire multi-file master/token/page group, and page overrides do not emit page-specific tokens. MASTER's authority is an upstream convention; Ox should retain DESIGN/tokens and document bounded exceptions rather than introduce a second authority.

Preview emits escaped HTML/CSS with restricted font URLs and system fallbacks; it may load Google Fonts remotely. Its contrast badges apply to color pairs. Neither preview existence nor a badge verifies native pixels, keyboard, screen reader, theme states or interactions. No preview was run.

CLI templates support many clients; Codex currently targets `.agents/skills/ui-ux-pro-max`. Init can distribute additional six skills and contains legacy release-download/fallback paths. Update can run global npm installation and forced refresh; init/template code can replace files and clean legacy paths. Inspection does not authorize running these effects. Source and bundled assets must remain in sync; do not copy the entire installer into Ox to obtain a few principles.

The upstream includes data/schema/freshness/RTL/IME/text-layout/token/preview/search tests, CLI e2e and a relevance evaluator. Evaluator statically binds runtime and judgments and measures routing/P@k/MRR/nDCG/abstention/coherence over calibration and held-out fixtures. This is materially stronger than count-only claims, but does not measure visual output, user task success or model effectiveness. No upstream tests or claimed scores were reproduced here.

## Recommended local integration

Refactor three existing skills: design-system owns brief/composition/layout choice, semantic tokens/type/state patterns; design-review owns observed visual quality and consequential recovery/keyboard findings; iced-engineering owns geometry feasibility and state/focus/render handoff. Preserve software-architecture/software-design as structural/code responsibilities. Add targeted references rather than seven new catchall skills or thousands of rows. Keep local authority, input-based acceptance, representative content and explicit unverified capabilities. Evaluate with realistic forward tasks in a separate context; treat textual scenario success as method evidence only, never native application acceptance or proof of better visuals.
