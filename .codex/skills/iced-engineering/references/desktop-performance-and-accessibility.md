# Responsiveness and accessibility evidence

Instrument input receipt, update completion, frame presentation where available, queue length and worker activity. Define a workload and hardware before setting thresholds. Compare idle, active computation, burst events and hidden panels; report percentile latency only from an actual sample with its size and method.

Cache heavy layouts by data generation and relevant layout parameters. When a graph is hidden, stop scheduling its layout and redraw triggers; preserving the last cache is different from keeping a loop alive. Cancellation and stale-result checks are both needed when computation is already running.

Review keyboard-only navigation, focus restoration, contrast, scale, labels and non-color state indicators. Test assistive technology on each supported platform before claiming accessibility. A state-transition unit test covers neither screen-reader output nor frame timing. Capture failures and explicit platform gaps alongside successful observations.
