# Specification: visual technical documentation

The maintainer requests refactoring technical-documentation to use Mermaid and
produce professional diagrams, charts, flows and imagery, translating aesthetic
terms into technical and measurable criteria. This is skill/library work, not
application UI implementation or retroactive redesign of existing documentation.

## Requirements and acceptance

- REQ-01: Preserve source-grounded tutorials, how-to, API references and explanations; add visual planning, appropriate Mermaid use and renderer/export compatibility.
- REQ-02: Define beauty/enterprise/modern in observable layout, typography, iconography, accessibility, data integrity and maintenance terms, separating defaults from standards.
- REQ-03: Route detailed diagram, icon/image/chart and review guidance without mandatory external services, unnecessary decoration or fabricated evidence/data.
- REQ-04: Preserve original imported bytes and unrelated work, register only the reviewed skill/bridge/resources, and reject unknown mutations, missing/escaping predecessors and extra resources.
- AC-01 → REQ-01: Inspect the revised entry and exercise a realistic documentation request; grounded contracts, Mermaid selection, compatibility/fallback and truthful render status remain explicit.
- AC-02 → REQ-02: Review the quality rubric against measurable pass/fail cases; no generic aesthetic adjectives alone approve a deliverable, and blockers cannot be averaged away.
- AC-03 → REQ-03: Inspect routed resources and evaluate failure cases for unsupported icons, missing chart data, altered screenshots and absent rendering; no invented observations or remote upload is required.
- AC-04 → REQ-04: Run targeted preservation tests with exact restoration, corruption, deletion, escape, duplicate/scope and new-resource mutations; compare current governance diagnostics with baseline and preserve old observations.

## Limits

No profile count change, Rust changes, commits, publication, global installation,
external document upload or rewrite of the earlier README task. The inherited
README current-byte guard failure is recorded separately, not waived. A skill
review is not proof that every future output is visually usable or WCAG conformant.
