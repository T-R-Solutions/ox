# SDD bridge: readme-lifecycle-engineering

This bridge is configured for Ox. When copied to another consumer, configure its
actual project-relative path to the complete skill folder's `SKILL.md`. Verify the entry's `name`, file existence and reference links. The skill can
be used without SDD or this bridge. Catalog presence alone never activates it.

## Selection

Choose for root/package README authoring, audit, splitting, navigation, onboarding and
synchronization with evolving product behavior. Do not use it for a general manual or
API reference alone (`technical-documentation`), source-code design decisions
(`software-architecture`) or documentation-theme styling.

## Inputs and contributions

Supply selected requirement/acceptance IDs, decisions/risks, task scope, actual repository
revision, readers, existing READMEs and linked docs, source of supported commands and status,
and actual authorization to inspect/run commands.

| Artifact | Contribution |
|---|---|
| Constitution | Respect actual repository documentation rules, product truthfulness, permissions, configuration authority and preservation. Create no new project policy. |
| Spec | Specify reader tasks, support status and observable onboarding/documentation acceptance; list unacceptable stale or fabricated outcomes. |
| Plan / ADR | Compare one-vs-multiple-README options, canonical ownership, migration/link implications and verification methods; record decision status and risks. |
| Tasks | Name files, exact impacted links, safe checks and existing tools; keep changes bounded and protect unrelated edits. |
| Evidence / convergence | Record revision, changed README path(s), source cross-checks, link/render results, executed safe commands, actual outputs, reader review and limitations. |

## Conditional handoff

Use a specialist only for a concrete question outside README lifecycle (e.g., verified
supported CLI command or product schema). Pass IDs, evidence needed and permission scope;
no recursive chain or unsupported claim that another skill was applied.

## Completion and authority

Honor the destination project's acceptance status vocabulary. Separate structural checks,
rendering, actual onboarding execution and user studies. `UNVERIFIED` or its local equivalent
applies when commands/environments are unavailable; a link checker PASS is not evidence that
a feature was implemented. Preserve requirement → decision → task → artifact → current evidence
traceability. This optional bridge grants no publication, install or production authority.
