# SDD bridge: engineering-productivity

Copy this optional bridge into the destination sdd/chain directory and configure
the project-relative path to the copied SKILL.md. Read the selected skill for the
method. Presence in the catalog does not activate it or install other skills.

## Selection

Use for a feature or improvement deciding between engineering tools/workflows or
evaluating a bounded process change. Do not select for runtime profiling, product
analytics, individual rankings or ordinary implementation. Record selection and
the unresolved decision in the feature plan.

## Inputs and contributions

| Artifact | Required input / contribution |
| --- | --- |
| Constitution | Read existing data permissions, decision authority and working constraints; introduce no employee-monitoring or collection policy. |
| Spec | Identify the decision, affected engineering population/task, desired outcome and observations that would change the action. Do not invent productivity quotas or individual scores. |
| Plan / ADR | Link requirement/decision/risk IDs to goal → signal → measure, options, method, baseline, confounders, authorized data and cost. A decision to avoid an uninformative study is valid. |
| Tasks | Name the bounded analysis or authorized pilot, actual inputs/tools, observation/stopping conditions and expected deliverable. A protocol does not authorize collecting data, contacting people or changing their tools. |
| Evidence / convergence | Return criterion IDs, observations, uncertainty, action, responsible role and follow-up trigger. Distinguish proposal, executed collection and association from supported causal evidence. |

## Conditional handoff

Consult performance-engineering only if a specific machine-cost mechanism remains
unresolved and that skill is available. Supply task/criterion IDs, workload,
observations, constraints and existing permission scope. Do not recursively load
specialists or treat their absence as work completed.

## Completion and authority

Use the destination SDD's outcome vocabulary with evidence or explicit pending/
inconclusive status for each applicable criterion. Spec owns the desired outcome;
plan/ADRs own decisions and tasks own executable work. The bridge neither changes
those authorities nor grants data access, rollout, outreach or spending permission.

## Perfil condicional do projeto

Avaliação de fluxo humano ou ferramenta com baseline e resultado observável; não benchmark do binário. Disponibilidade não significa seleção, consulta ou uso.
